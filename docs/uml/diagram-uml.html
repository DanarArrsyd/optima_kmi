Diagram UML — Laporan Kerja Praktek OPTIMA

Rancang Bangun Sistem Informasi Manajemen Produksi dan Pengukuran Overall Equipment Effectiveness Berbasis Web pada PT. Kenco Manufactur Indonesia · Bagian 3.6.1 Use Case Diagram

Cara mengunduh untuk ditempel di Word. Setiap diagram memiliki dua tombol di bawahnya.
  1. Unduh PNG 4× menghasilkan berkas raster berlatar putih pada empat kali ukuran asli, sekitar 3.400 sampai 4.000 piksel lebar. Ukuran itu memadai untuk dicetak pada 300 dpi. Pakai ini untuk pemakaian biasa.
  2. Unduh SVG menghasilkan berkas vektor tanpa batas resolusi. Microsoft Word mendukung penyisipan SVG secara langsung, dan hasil cetaknya lebih tajam daripada PNG. Pakai ini apabila dokumen akhirnya dicetak.
Berkas yang terunduh hanya memuat gambar. Nomor dan judul gambar yang tampil di bawah diagram pada halaman ini tidak disertakan, karena keduanya harus ditulis sebagai teks di Word agar masuk Daftar Gambar secara otomatis.
Peringatan sebelum memakai plantuml.com. Merender melalui server publik berarti mengirim sumber diagram ke pihak ketiga. Isinya rancangan sistem internal: nama peran, alur data, dan struktur modul. Untuk menghindarinya, render lokal dengan plantuml.jar atau ekstensi PlantUML di VS Code yang dikonfigurasi memakai server lokal.

Gambar 3.6 — Activity Diagram Pemasukan Laporan Hasil Produksi

Menggambarkan UC-04. Memenuhi KF-02, KF-06, dan KF-10. Bandingkan dengan Gambar 3.2: pemeriksaan kewajaran dan penandaan anomali tidak memiliki padanan pada sistem yang berjalan.

Gambar 3.6 Activity Diagram Pemasukan Laporan Hasil Produksi
Sumber PlantUML — Gambar 3.6 
@startuml
skinparam monochrome true
skinparam shadowing false
skinparam defaultFontName Times New Roman
skinparam defaultFontSize 13

|Staf Produksi|
start
:Membuka formulir Laporan
Hasil Produksi;
repeat
  :Mengisi data produksi
  pada formulir;
  :Mengirimkan formulir;
  |Sistem|
  :Memeriksa acuan data master
  dan kewajaran masukan;
backward:Memperbaiki masukan;
repeat while (Masukan sah?) is (Tidak) not (Ya)
:Menyimpan data dan memperbarui
akumulasi stroke;
:Memeriksa kewajaran SPH aktual;
if (Melewati ambang?) then (Ya)
  :Menandai data sebagai anomali;
else (Tidak)
endif
stop
@enduml

Gambar 3.7 — Activity Diagram Perhitungan dan Penyajian OEE

Menggambarkan UC-15. Memenuhi KF-07, KF-09, dan KF-12. Dua lajur menunjukkan pihak yang meminta dan pihak yang menghitung. Cabang pemeriksaan jam terjadwal menjawab keadaan ketika seluruh hari dalam rentang bukan hari kerja, sehingga penyebut bernilai nol, dan hasil cabang itu tetap disampaikan kepada peminta.

Gambar 3.7 Activity Diagram Perhitungan dan Penyajian OEE
Sumber PlantUML — Gambar 3.7 
@startuml
skinparam monochrome true
skinparam shadowing false
skinparam defaultFontName Times New Roman
skinparam defaultFontSize 13

|Manajer|
start
:Memilih rentang tanggal
yang akan ditampilkan;
:Mengirim permintaan;
|Sistem|
:Menentukan hari kerja, mengecualikan
hari Minggu dan hari libur;
:Menghitung jam kerja terjadwal
dari data master shift;
if (Jam terjadwal lebih dari nol?) then (Ya)
  :Menjumlahkan waktu henti perbaikan
  dan waktu penggantian dies;
  :Menghitung Availability;
  :Menghitung jam produktif
  per mesin per tanggal;
  :Menghitung Performance;
  :Menghitung Quality dari jumlah
  produk baik dan produk cacat;
  :Mengalikan ketiga faktor
  menjadi nilai OEE;
  :Menyajikan nilai OEE per mesin;
else (Tidak)
  :Menyatakan nilai
  tidak tersedia;
endif
|Manajer|
:Menerima dan membaca
nilai OEE per mesin;
stop
@enduml

Gambar 3.8 — Sequence Diagram Pemasukan Laporan Hasil Produksi

Urutan interaksi pada UC-04. Pemeriksaan berlangsung di Controller sebelum data mencapai Model, sehingga masukan yang tidak sah tidak pernah menyentuh basis data.

Gambar 3.8 Sequence Diagram Pemasukan Laporan Hasil Produksi
Sumber PlantUML — Gambar 3.8 
@startuml
skinparam monochrome true
skinparam shadowing false
skinparam defaultFontName Times New Roman
skinparam defaultFontSize 13
skinparam sequenceMessageAlign left

actor "Staf Produksi" as SP
participant "Antarmuka" as UI
participant "ProduksiController" as PC
participant "TransaksiProduksi" as TP
database "Basis Data" as DB

SP -> UI : mengisi dan mengirim formulir
UI -> PC : kirim data produksi
PC -> PC : periksa acuan data master\ndan kewajaran masukan
PC --> UI : [tidak sah] pesan kesalahan
PC -> TP : [sah] simpan data
TP -> DB : simpan transaksi produksi
DB --> TP : konfirmasi penyimpanan
TP -> DB : perbarui akumulasi stroke
PC --> UI : hasil penyimpanan
UI --> SP : tampilkan konfirmasi
@enduml
